인제스트된 논문 페이지를 읽고 지식을 합성해 위키를 업데이트한다.

## 인수
`/wiki:synthesize [범위] [키워드]`
- 범위 없이 호출: 마지막 synthesis 이후 추가된 모든 논문 대상
- `sna`: `pages/papers/sna/` 대상 (SNA 학술지 논문)
- `applied`: `pages/papers/applied/` 대상 (응용 분야 논문)
- `all`: 전체 대상
- 키워드 추가 시 해당 주제에 집중 (예: `applied gnn`, `sna ergm`)

## 절차

### 1. 대상 파악
- 범위에 해당하는 논문 페이지 목록 수집
- 규모에 따라 전략 결정:
  - ~50편: 직접 읽고 합성
  - 51~200편: 에이전트 4개로 분할 탐색 후 결과 합산
  - 200편 초과: 에이전트 8~10개 병렬 탐색 후 결과 합산

### 2. 병렬 탐색 (규모가 클 때)

각 에이전트에게 청크를 배분하고 **단일 메시지로 동시에 spawn**한다.

**탐색 에이전트 프롬프트 형식**:
```
다음 논문 페이지들을 읽고 아래 항목을 추출해줘.

파일 목록: [파일 경로 목록]

추출 항목:
1. 사용된 방법론 목록 (논문명, 방법론명)
2. 응용 분야 (마케팅/보건/경영/커뮤니케이션 등)
3. 사용 도구 (소프트웨어, 라이브러리)
4. NetMiner로 커버 가능한 워크플로우 여부
5. 특이한 트렌드나 패턴

결과를 구조화된 목록으로 반환.
```

모든 탐색 에이전트 완료 후 결과를 합산해 전체 패턴 파악.

### 3. 지식 합성 및 페이지 업데이트

아래 순서로 업데이트한다. 각 항목은 필요한 경우에만 수행.

#### 3-1. methods/ 페이지 보강
- 새로 발견된 방법론 사용 패턴을 기존 methods 페이지에 추가
  - 응용 분야 사례: `applied/` 논문 링크 + 한 줄 맥락
  - 새 변형·기법이 발견되면 별도 섹션 추가
- 기존 pages/methods/ 에 없는 중요 방법론이면 새 페이지 생성

#### 3-2. concepts/ 페이지 보강
- 연구 설계 패턴 중 새로운 패턴 발견 시 해당 페이지에 추가
- 응용 분야에서 새로운 설계 패턴이 등장하면 새 페이지 생성 고려

#### 3-3. insights/ 페이지 생성·업데이트
- 합성 결과 중 저장 가치 있는 분석은 insights 페이지로 저장
- 파일명: `YYYY-MM-DD_주제_슬러그.md` 또는 기존 페이지 업데이트
- 반드시 분석 기준(날짜·대상 편수·범위) 명시

  **applied 대상 시 우선 생성할 insights**:
  - 응용 분야별 SNA/텍스트마이닝 활용 빈도
  - 분야별 자주 쓰이는 방법론 조합
  - NetMiner 연결 가능성이 높은 워크플로우 패턴

#### 3-4. tools/ 페이지 보강
- 논문에서 새로 발견된 도구(소프트웨어, 라이브러리) → `other_tools.md`에 추가
- NetMiner 대비 포지셔닝 업데이트

#### 3-5. overview.md 갱신
- **SNA 논문(`sna`) 합성 시**: Part 2 (학계 트렌드) 갱신
- **응용 분야(`applied`) 합성 시**: Part 3 신설 또는 갱신
  - 응용 분야별 SNA 활용 현황
  - NetMiner 제품 기획 시사점 (신규 고객 세그먼트, 기능 수요)
- **전체(`all`)**: 두 파트 모두 갱신

### 4. index.md 업데이트
- 새로 생성된 insights/methods/concepts 페이지를 해당 섹션에 추가
- 통계 수치 갱신

### 5. log.md 기록
```
## [YYYY-MM-DD] synthesize | 범위·주제
- 대상: N편 (pages/papers/범위/)
- 업데이트: methods N개, concepts N개, insights N개, tools N개
- 핵심 발견: 1–2줄
```

## 규칙
- 논문 페이지를 직접 수정하지 않는다 (읽기만)
- `raw/` 파일은 참조하지 않는다 (pages/ 기준)
- 기존 페이지 업데이트 시 기존 내용을 지우지 않고 추가·보강한다
- 인사이트는 추정이 아닌 실제 논문 근거 기반으로 작성
- NetMiner 관련 시사점은 항상 "학술 수요(편수)" vs "NetMiner 지원 여부"를 분리해서 서술
