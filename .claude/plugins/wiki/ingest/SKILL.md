새 소스를 위키에 통합한다.

## 인수
`/wiki:ingest [파일명 또는 경로]`
- 인수 없이 호출하면 `D:\soojin\wiki\raw\`에서 index.md에 등록되지 않은 파일을 탐지해 모두 처리한다.
- 인수를 주면 해당 파일만 처리한다 (raw/ 기준 상대경로 또는 절대경로 모두 허용).

## 절차

### 1. 소스 파악
- 처리할 파일 목록 확인
- PDF면 PyMuPDF(fitz)로 텍스트 추출 (가상환경: `D:\soojin\.venv`)
- 마크다운이면 직접 읽기

### 2. 내용 분석
- 소스 유형 판단: 논문 / 기사 / 보고서 / 기타
- 핵심 내용 파악: 연구질문, 방법론, 주요 결과, 사용 도구

### 3. 페이지 생성
소스 유형에 따라 적절한 카테고리에 생성:

**논문** → `pages/papers/YYYY_저자성_키워드.md`
```yaml
---
title:
authors: []
year:
venue:
tags: []
source: raw/파일명
---
```
내용 (한국어 번역 포함):
- **제목(한글)**: 논문 제목 한국어 번역
- **연구질문**: 1–2문장 한국어 요약
- **방법론**: 한국어 표 또는 불릿
- **주요 결과**: 핵심 발견 한국어 불릿
- **초록(원문)**: 영어 원문 초록
- **NetMiner 연관성** / **메모**

**기사·보고서** → `pages/papers/YYYY_출처_키워드.md` 또는 적절한 카테고리

### 4. 관련 페이지 업데이트
- `pages/concepts/`, `pages/methods/`, `pages/tools/` 중 관련 페이지를 찾아 업데이트
  - 없으면 새 페이지 생성
- 모든 페이지에 새 논문으로의 위키링크 추가

### 5. overview.md 갱신
- 새 소스에서 나타난 트렌드를 해당 섹션에 반영
- "미해결 질문" 섹션에 추가 조사 항목 제안

### 6. index.md 업데이트
- 새로 생성된 모든 페이지를 해당 섹션에 추가 (형식: `- [[경로|제목]] — 한 줄 요약 (#태그)`)
- 통계 (총 페이지 수, 소스 수, 최근 업데이트) 갱신

### 7. log.md 기록
```
## [YYYY-MM-DD] ingest | 소스 제목
- 처리 파일: 파일명
- 생성 페이지: N개
- 업데이트 페이지: N개
- 핵심 인사이트: 1~2줄
```

## 규칙
- `raw/` 파일은 절대 수정하지 않는다
- 위키링크는 `[[파일경로|표시텍스트]]` 형식
- 모든 신규 페이지는 최소 2개 위키링크 포함
- NetMiner 관련 내용이 있으면 반드시 `pages/tools/netminer.md`에 사례 추가
